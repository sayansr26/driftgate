# Determinism

Identical canonical input must produce byte-identical output on every run, platform,
Node version, locale, and filesystem. This is a contract (RFC-0001 §9), not an
aspiration. **Nondeterminism is a P0 bug.**

## Why it is load-bearing

`driftgate check` regenerates artifacts in memory and compares them to what is on
disk. If rendering could vary by machine, `check` would fail on a colleague's laptop
or in CI for reasons that have nothing to do with drift — and a verification tool that
cries wolf is worse than no verification tool, because people learn to ignore it.

Determinism is what makes `check` mean something.

## The rules

### 1. Never `os.EOL`

Output is `\n`, always. Node performs no translation on any platform, so writing `\n`
produces `\n` everywhere. Lint-enforced.

### 2. Never `localeCompare`, `Intl.*`, or `toLocaleString`

Locale-sensitive comparison varies by host locale _and_ by ICU build. Use
`compareCodepoint`. Codepoint order is not linguistically ideal; it is identical
everywhere, which is what matters. Lint-enforced.

### 3. Never rely on object key order

Everything serialized to JSON goes through `stableJsonStringify`, which sorts keys.
V8's insertion order is well-defined, but the _insertion_ order is not — objects built
from a filesystem walk inherit that walk's ordering.

### 4. Never trust `readdir` order

APFS, ext4, and NTFS return entries in different orders. `ReadOnlyFileSystem.listDir`
and `.glob` sort before returning, so adapters cannot obtain an unsorted listing even
by accident. Sorting lives at the boundary rather than in author discipline.

### 5. No environment in output

No timestamps, tool versions, hostnames, usernames, absolute paths, or random values
may appear in a generated byte. This is why `state.json` has no `generatedAt` field:
it would make "delete state.json, re-sync, get identical bytes" impossible, and would
put a spurious diff in every repository on every Driftgate upgrade.

### 6. Normalize on read

Every text read strips the BOM and converts `\r\n` and `\r` to `\n`, at the io
boundary. A CRLF checkout and an LF checkout therefore parse to the same model.

Hashing follows the same rule: `state.json` stores hashes of **normalized** content.
Hashing raw bytes would mean every Windows user with `core.autocrlf=true` sees every
generated file report as hand-edited on every checkout, failing `check` in CI for
every repository on that platform.

### 7. POSIX separators inside content

Any path appearing _within_ a generated file uses `/`. Native separators exist only in
`repoRoot` and inside the io layer.

### 8. NFC-normalize filename-derived identifiers

macOS returns decomposed (NFD) filenames; Linux returns composed (NFC). A rule named
`café.md` would otherwise carry a different id per platform — and since ids break
ordering ties, the same repository would render different bytes on macOS and Linux.

Note that APFS also normalizes on _lookup_, so two files whose names differ only by
normalization silently become one file on macOS while remaining two on ext4.

### 9. UTF-8 without a BOM

One `writeFile(path, string, 'utf8')` call. BOMs are stripped on read and never
written.

### 10. Sets and Maps become sorted arrays before rendering

Never iterate a `Set` directly into output.

## How this is enforced

| Mechanism                                | Catches                                                                                             |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| ESLint `no-restricted-syntax`            | `os.EOL`, `localeCompare` at author time.                                                           |
| `packages/core/test/invariants.test.ts`  | The same primitives, plus `Math.random`, across all shipped source.                                 |
| `packages/core/test/determinism.test.ts` | 100 renders → one hash; 200 seeded shuffles → one ordering; LF and CRLF fixtures → identical bytes. |
| `fixtures/eol/{lf,crlf}`                 | End-to-end EOL insensitivity, from parse through render.                                            |
| `.gitattributes` `fixtures/** -text`     | Git itself translating the fixtures and quietly destroying the test.                                |

## Adding a renderer

1. Route all output through `finalizeArtifact`.
2. Sort every collection with `compareCodepoint` or `sortRules`.
3. Add the output to a golden fixture asserted byte-exact.
4. If it emits JSON, use `stableJsonStringify`.

If you cannot make output deterministic, the feature is wrong, not the rule.
