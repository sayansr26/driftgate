# Golden fixtures

Every adapter owns a real mini-repository here, and its output is asserted **byte-exact**.
Adapter regressions are P0 (NFR5): tool formats change without notice, and fixtures are how
we find out before users do.

## Two layouts, because there are two questions

```
fixtures/<tool>/input/          a repo with a .driftgate/
fixtures/<tool>/expected/       exactly the bytes the adapter must produce from it

fixtures/<tool>-detect/positive/   a repo where detect() must find the tool
fixtures/<tool>-detect/negative/   a repo where it must not
```

They differ because the situations differ: a detect fixture is a whole repository that
either shows the tool's fingerprints or does not, and it has no expected output — often no
`.driftgate/` at all, since `detect()` runs on repositories that have not adopted Driftgate
yet. That is the first step of `init`.

Never build the subpath by hand. `@driftgate/adapter-kit/testing` resolves both shapes:

```ts
import { detectFixture, expectFixtureMatch, expectIdempotent } from '@driftgate/adapter-kit/testing';

await expectFixtureMatch('cursor', cursor);                  // input/ vs expected/
await expectIdempotent('cursor', cursor);                    // 10 renders, identical bytes
await contextFor(detectFixture('cursor', 'positive'), cursor);
```

## Adding a fixture

**Hand-write `expected/` first**, from the tool's documented behavior, before implementing
`detect` → `read` → `write`. This is the whole point of the fixture: output generated by the
adapter it is meant to check proves only that the adapter agrees with itself. The `.mdc`
dialect was caught this way at T007 — it looks like YAML and is not.

## Regenerating

```
pnpm build && pnpm fixtures:update            # prints the change set, writes nothing
pnpm build && pnpm fixtures:update --yes      # applies it
pnpm build && pnpm fixtures:update cursor     # one fixture
```

It refuses to run when `CI` is set, nothing in `pnpm test` imports it, and it writes only
under `fixtures/<tool>/expected/`. It also **deletes** goldens the adapter no longer
produces — a stale golden left behind is how a dropped artifact escapes notice.

Use it for an intended change that touches many fixtures at once. If a fixture fails and you
did not intend the change, that is an adapter regression, not a stale golden.

## Do not reformat

`fixtures/**` is in `.prettierignore` and `.eslintignore`, and `.gitattributes` sets
`fixtures/** -text` so Git never rewrites line endings here. `fixtures/eol/` exists
specifically to prove CRLF input produces LF output; a checkout that normalized it would
make that test meaningless.
